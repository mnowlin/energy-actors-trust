Project title: Who Does the Public Trust on Energy Issues?
Project name: energy-actors-trust

This is an academic article about who the public trusts with regard to energy policy and how that trust influences concern about energy issues. 

You are to help me with the R code and managing the github repository for this project. Use the renv package in R to ensure all analysis can be reproduced. All text for the manuscript will be generated by me. If asked to generate draft text refer to nowlin-style-profile. 

I use a .qmd file for the manuscript and all text and code needs to produce an html, pdf, and docx document. The `export-cited-refs.R` file is code to pull cited references from a master bibliography to create a project-specific bibliography 

Use paperpush to help when submitting a manuscript: /paperpush-plugin:paperpush-prepare-submission 

## Set up project 
When I say “set-up [project name]”:
1. Copy all contents from the project-files template directory (local-only path; not stored in this public repo — see Claude Code's saved reference memory for the path). 
2. Change the name of template.qmd to [project name].qmd. This is the manuscript file
3. Change the title in [project name].qmd YAML to project title
4. Change the render file name in _quarto.yaml using the project name
5. Update the README file for this project. The included file is from another project and acts as a template
6. Check the git status of the directory. It no git exists, create one and ask me if it should be public or private
7. Create a analysis.R file in the scripts directory. This will contain the code file for the analysis presented in the manuscript. Tables and figures will use code blocks in the manuscript file. Some inline R code will also be used
8. Update the log file. The included file is from another project and acts as a template
9. Update the export-cited-refs file with the correct qmd file name for this project
10. Add /data, /literature, and nowlin-style-profile.md to gitignore
11. Hide the path to the project folder in step 1 before committing and pushing this file

## Close out
When I say "close out"
1. update the log 
2. update the README file if needed
